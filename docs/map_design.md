# 긴 맵 설계안 (초안)

지금 테스트 맵(`TEST_MAP`, 167줄)을 대신할 긴 맵의 첫 설계안입니다.
아직 코드에는 넣지 않았습니다. 읽어 보고 고칠 점을 알려 주시면 반영한 뒤 `level_data.py`에 넣겠습니다.

- 꼭대기 바닥까지 **434줄** (지금은 134줄). 시작 위치 기준 높이로 **약 433m** (지금은 약 133m)
- 구간 4개는 그대로 (나무 → 벽돌 → 얼음 → 금). 구간마다 새 요소가 하나씩 나오고 위로 갈수록 어려워짐
- 실제 `Player` 물리로 모든 발판에서 점프를 시뮬레이션해서, **바닥에서 꼭대기 바닥까지 끝까지 올라갈 수 있는 것**을 확인함 (아래 8번 참고)

## 2. 탑 그림 조각과 구간 경계

탑 조각 하나는 화면에서 1600px (= 33.33줄)입니다. `asset/tower/tower_re/tower.json`의 쌓는 순서대로, 반복 조각을 넣어 14개를 쌓습니다.

| 순서 | 조각 | 줄 범위 (대략) |
|---|---|---|
| 0 | `tower_bottom` | 0 ~ 33 |
| 1~3 | `tower_wood` x3 | 33 ~ 133 |
| 4 | `tower_trans_wood_brick` | 133 ~ 167 (159줄에서 벽돌로 바뀜) |
| 5~6 | `tower_brick` x2 | 167 ~ 233 |
| 7 | `tower_trans_brick_frozen` | 233 ~ 267 (259줄에서 얼음으로 바뀜) |
| 8~9 | `tower_frozen` x2 | 267 ~ 333 |
| 10 | `tower_trans_frozen_gold` | 333 ~ 367 (359줄에서 금으로 바뀜) |
| 11~12 | `tower_gold` x2 | 367 ~ 433 |
| 13 | `tower_top` | 433 ~ 467 (434줄 바닥이 문 바로 아래) |

- 구간 경계(159 / 259 / 359줄)는 연결 조각 그림에서 벽 무늬가 바뀌는 높이(조각 아래에서 약 248px)에 맞춘 값입니다. 지금 맵의 59 / 92 / 126줄과 같은 방식으로 계산했습니다.
- 조각 수를 3의 배수 + 2개(14개)로 해서, 꼭대기 문 아래 바닥이 지금 맵과 똑같이 칸 경계에 딱 맞습니다.

## 3. 이 설계안을 넣을 때 바뀌는 코드 (아직 안 바꿈)

- `config.py`: `TOWER_PIECES`를 위 14개 목록으로 바꿈
- `level_data.py`: `LONG_MAP`, `LONG_ZONES = [(0, 'wood'), (159, 'brick'), (259, 'frozen'), (359, 'gold')]` 추가
  - `TEST_MAP`은 테스트용으로 남겨 둘지, 지울지 정해 주세요
- `main.py`: `TileMap(TEST_MAP, TEST_ZONES)` → `TileMap(LONG_MAP, LONG_ZONES)`
- 숫자 키 1~4 순간이동은 구간 시작 위치를 맵에서 찾아가므로 그대로 동작함
- 카메라·HUD(높이, 최고기록)는 맵 높이를 따로 정해 두지 않아서 고칠 것 없음

## 4. 설계 규칙 (점프 수치 기준)

모든 수치는 지금 코드(`config.py`) 그대로입니다. FPS와 상관없이 같습니다.

| 항목 | 값 | 맵에서의 의미 |
|---|---|---|
| 점프 높이 | 119px (약 2.5칸) | 발판은 한 번에 **최대 2줄 위**까지 |
| 같은 높이 점프 거리 | 약 244px (약 5칸) | 같은 높이면 빈 칸 4칸까지 |
| 2줄 위로 뛸 때 | 가로 약 180px | 2줄 위 발판은 빈 칸 **3칸까지** |
| 1줄 위로 뛸 때 | 가로 약 218px | 1줄 위 발판은 빈 칸 4칸까지 |
| 머리가 닿는 높이 | 서 있는 줄 + 약 3.85줄 | 발판 바로 위 3줄 안에 다른 블록을 두지 않음 (점프가 막힘) |
| 높이 떨어져 넘어짐 | 약 7칸 이상 낙하 | 떨어지면 넘어지지만 죽지는 않음. 실수하면 아래 발판으로 떨어져 다시 올라감 |

경로를 만든 방식:

1. 바닥에서 시작해 한쪽으로 발판을 계단처럼 놓음 (2줄 위 / 1줄 위 / 같은 높이 중 하나, 빈 칸은 위 표 범위 안)
2. 벽 가까이(양쪽 5칸)에 닿으면 **벽에 붙은 넓은 발판 + 벽 쪽 2칸 턱(2줄 높이)**을 놓고 방향을 바꿈. 지금 맵의 벽 경사와 비슷한 리듬으로 약 15줄마다 한 번씩 꺾임
3. 비어 있는 벽에는 지금 맵과 같은 모양의 벽 경사(왼쪽 `\ #\ ##\ ###\ ###[ ##[ #[ [`, 오른쪽은 반대)를 붙여 탑 벽 느낌을 냄
4. 새 발판은 아래 발판의 머리 공간이나 이미 놓은 점프 경로를 막지 않는 자리에만 놓음
5. 블록 발판 일부는 두 줄로 두껍게 하고 아랫줄 양 끝을 천장 경사(`]###[`)로 만들어 지금 맵의 덩어리 모양을 따름

## 5. 구간별 구성

### 나무 (0~158줄) - 익히는 구간
- 넓은 발판(3~5칸), 대부분 블록 `#`, 30% 정도 얇은 발판 `=`
- 고블린 `G`, 지뢰 `M`, 박쥐 `B`가 처음 나옴
- **61~63줄**: 부서지는 발판 `C` 첫 등장 (3개 연속)
- **101줄**: 좌우로 움직이는 발판 `H` 첫 등장 (같은 높이 먼 발판을 이어 줌)
- **126줄**: 레이저 첫 등장. 빈틈 아래에서 위로 쏘는 주기형 `U` (받는 장치 `*` 132줄)
- 115줄: 궁수 `A` 한 명을 미리 보여 줌

### 벽돌 (159~258줄) - 원거리 적과 함정
- 발판이 좁아짐(2~4칸), 같은 높이 점프가 조금 늘어남
- 궁수 `A`가 벽 쪽 넓은 발판에서 기다림, 가고일 `K` 첫 등장
- **176줄, 231줄**: 좌우 움직이는 발판
- **192~194줄, 248~251줄**: 부서지는 발판 3개 연속
- **208줄**: 감지형 레이저 `u` (플레이어가 줄 위에 오면 발사, 받는 장치 214줄)

### 얼음 (259~358줄) - 미끄러움 + 위아래 발판
- 모든 발판이 얼음 `I` / `~` (미끄러움). 착지 후 미끄러질 공간을 생각해 발판을 다시 넓게(3~5칸)
- 서리 마법사 `F` 첫 등장 (주로 벽 쪽 발판), 가고일 `K`
- **268줄, 290줄, 333줄**: 위아래로 움직이는 발판 `V` (5~7줄을 타고 올라감)
- **312줄**: 좌우 움직이는 발판 (얼음 위라 미끄러움)
- **352줄**: 감지형 레이저 (받는 장치 358줄)

### 금 (359~434줄) - 종합
- 가장 좁은 발판(1~3칸), 1칸짜리는 절반 확률로 반 칸 발판 `-`
- 궁수·가고일·지뢰가 가장 많음
- **371~373줄, 419~422줄**: 부서지는 발판
- **380줄**: 좌우 움직이는 발판 / **395줄**: 위아래 움직이는 발판
- **414줄**: 감지형 레이저 (받는 장치 420줄)
- **434줄**: 꼭대기 바닥 (가운데 9~18칸, 탑 문 바로 아래). 그 위 435~466줄은 비워 둠 (탑 꼭대기 그림 공간)

## 6. 기호표

| 기호 | 뜻 |
|---|---|
| `.` | 빈 칸 |
| `\|` | 탑 안쪽 벽 (아래 맵에서 양쪽 끝. 실제 파일에서는 바깥에 `.....`가 더 붙음) |
| `#` | 블록 (구간에 따라 나무/벽돌/얼음/금 무늬) |
| `I` | 얼음 블록 (미끄러움) |
| `=` | 얇은 발판 / `~` 얇은 얼음 발판 (미끄러움) |
| `-` | 반 칸 발판 (칸 가운데 24px) |
| `\` `/` | 바닥 경사 (밟으면 낮은 쪽으로 미끄러짐) |
| `[` `]` | 천장 경사 |
| `P` | 시작 위치 |
| `G` | 고블린 / `B` 박쥐 (위아래 `:` 칸까지 날아다님) / `M` 지뢰 |
| `A` | 고블린 궁수 / `K` 가고일 / `F` 서리 마법사 |
| `C` | 부서지는 발판 |
| `H` | 좌우로 움직이는 발판 (같은 줄 `_` 칸까지) |
| `V` | 위아래로 움직이는 발판 (첫 칸 위 `_` 칸까지) |
| `U` / `u` | 위로 쏘는 레이저 (대문자 주기형 / 소문자 감지형), `*` 받는 장치 |

## 8. 확인한 것 / 확인 못 한 것

**확인함**
- 실제 `Player` 코드로 각 발판의 양 끝과 가운데에서 점프(누르는 시간 3가지, 방향, 늦게 누르기, 중간에 떼기)와 걸어서 떨어지기를 시뮬레이션함. 시작 위치에서 **꼭대기 바닥(435줄)까지 모든 발판에 갈 수 있음**
- 같은 검사로 지금 테스트 맵도 꼭대기까지 갈 수 있는지 확인해서 검사 방법이 맞는지 봄

**확인 못 함 (직접 플레이해 봐야 함)**
- 적·지뢰·레이저·박쥐는 검사에서 뺐음 (피하거나 처치할 수 있다고 봄). 위치가 너무 가혹한 곳이 있을 수 있음
- 움직이는 발판은 "처음 자리와 범위 양 끝에 잠깐 있는 발판"으로, 부서지는 발판은 "보통 발판"으로 보고 검사함. 타이밍이 빡빡한 곳이 있을 수 있음
- 얼음 구간에서 착지 후 미끄러져 떨어지는지는 검사하지 않음 (얼음 끝에서 바깥으로 미끄러지는 규칙)
- 총 반동 점프(공중에서 한 번 약 0.7칸 더 뜸)는 경로에 쓰지 않았음. 없어도 올라갈 수 있게 만듦

## 9. 정해 주시면 좋은 것

1. **길이**: 지금 434줄(약 433m)이 적당한지. 탑 조각을 3개씩 빼거나 더하면 꼭대기 문 위치가 칸에 맞게 유지됩니다 (예: 11개 = 334줄, 17개 = 534줄)
2. **구간 비율**: 나무 159 / 벽돌 100 / 얼음 100 / 금 76줄
3. **난이도**: 특히 금 구간의 1칸·반 칸 발판, 벽돌 구간 가고일 수
4. **`TEST_MAP`**: 남겨 둘지 (예: 다른 키로 테스트 맵 열기) 지울지
5. **꼭대기**: 문 앞 바닥에 마지막 적을 둘지, 도착하면 무언가(엔딩 화면 등)를 띄울지
